# QA: "Note for the app" quick capture — 2026-10-26
Tested: in browser (built-in browser pane, 1280px + 375px, dark + light, keyboard, focus mode via ⌘⇧I), local test DB
Brief: the single user mid-work · type a note, pick Idea/Improvement/Bug, "Save note" (⌘↵) · box clears, "Saved" shows, note appears in the list (given)
Stranger test: "This screen is for jotting a quick idea or bug about the app, and it wants me to type it and save it." ✓ matches the brief
Verdict: fix needed (1 High, 5 Medium, 4 Low)

## Findings
- [High] A note with a long unbroken word (URL, path, error string) pushes the textarea, Save button, "Show done" and the list outside the dialog. Desktop: dialog 512px wide, content 791px. At 375px the Save button is off-screen. Persists every time the dialog opens while that note is listed. — app-notes-dialog.tsx:101 (DialogContent grid has no `minmax(0,1fr)` column), :196 (`break-words` doesn't shrink min-content) — broken layout / long content — fix: add `grid-cols-[minmax(0,1fr)]` (or `min-w-0` on the children) to DialogContent and use `[overflow-wrap:anywhere]` on the note text — shot: shots/2026-10-26-app-notes-1.jpg, -2.jpg
- [Medium] Escape while editing a note closes the whole dialog, not just the edit. `event.stopPropagation()` on the React event doesn't stop Base UI's document-level Escape handler. The edit is thrown away. — app-notes-dialog.tsx:185-188 — Esc should cancel the innermost thing — fix: intercept in `onOpenChange` (ignore close when `editingId` is set and reason is escape-key), or `event.preventDefault()` + Base UI's escape opt-out
- [Medium] Focus isn't returned on close. After Esc/✕ it lands on `<body>`, not on the lightbulb or the editor the user was typing in. When opened with ⌘⇧I mid-writing, "get back to work" means clicking back into the editor. — workspace.tsx (controlled dialog, no DialogTrigger) / app-notes-dialog.tsx:101 — keyboard / ADHD flow — fix: save `document.activeElement` when opening and pass it as `finalFocus` (or restore in onOpenChange)
- [Medium] After Mark done or Delete, keyboard focus drops to the dialog container, so a keyboard user loses their place. Mark done also gives no feedback; the row just disappears from the "open" list. — app-notes-dialog.tsx:209-235 — keyboard / success feedback — fix: move focus to the next row's action (or the Undo button after delete); optionally a small "Marked done" status line like the delete one
- [Medium] Contradictory empty state. With 0 open and 1 done note, the list says "0 open · Show done (1) · Nothing here yet. Your notes will show up here." It's not true that nothing is there. Also not the `EmptyState` pattern from DESIGN.md (small inline text is OK for a dialog, but the copy has to be right). — app-notes-dialog.tsx:162-165 — empty state — fix: when `doneCount > 0` say "All caught up — no open notes." — shot: shots/2026-10-26-app-notes-4.jpg
- [Medium] The meta line shows the raw view id ("todos", "content-planner", "chat") rather than user words ("Todos", "Content Planner", "From chat"). — app-notes-dialog.tsx:205 — voice / no tech words — fix: map the screen id to the nav label
- [Low] At 375px the three always-visible row icons and the type tag squeeze the note text into a narrow column, so a short note wraps over 5 lines. — app-notes-dialog.tsx:169-236 — fix: put the tag above the text on mobile, or put the actions in a "⋯" menu below `sm` — shot: shots/2026-10-26-app-notes-3.jpg
- [Low] "✓ Saved" stays next to the button after a later delete/done/edit until the user types. Stale feedback. — app-notes-dialog.tsx:52,125 — fix: clear `justSaved` after ~3s or on any other action
- [Low] The dialog is vertically centred, so it jumps up every time a note is added or the textarea grows. — DialogContent placement — fix: anchor near the top (e.g. top 10vh) for this dialog
- [Low] The tooltip and `aria-keyshortcuts` say ⌘⇧I on every platform. On Windows/Linux Chrome, Ctrl+Shift+I is the DevTools shortcut, and preventDefault may not win there (desktop debug builds too). — top-navbar.tsx:333, workspace.tsx:62 — fix: show Ctrl on non-Mac; check it doesn't fight DevTools in the Tauri shell

## What works
- The stranger sentence is clear: a title, a one-line purpose, a focused textarea, and one lilac primary "Save note".
- ⌘↵ saves (also after picking a type with the keyboard). The box clears, focus stays in it, and "Saved" + the new row appear right away.
- Double-click on Save doesn't duplicate. Save is disabled for empty text. The type picker is arrow-key operable.
- Delete → inline "Note deleted · Undo" works and restores the note. Show/Hide done works. Done notes are struck through.
- ⌘⇧I opens it in focus mode, above the focus overlay. Esc closes the dialog without leaving focus mode. The draft survives closing.
- Dark and light both read well. Tokens only, no hardcoded colors. Icon buttons have names. Bengali text renders fine.

## Couldn't test
- Read-only / "Connecting…" state, and failed sync while saving.
- Larger text (⌘+) and the mobile on-screen keyboard covering Save.
- The Tauri desktop shell (DevTools shortcut clash).
